<h1>Chapter 12 — HTTP, HTTPS &amp; Web Networking</h1>
<img width="800" height="1200" alt="image" src="https://github.com/user-attachments/assets/768a27f6-e454-48cd-a216-233e5a21176a" />

<p>
HTTP and HTTPS are protocols used for communication between web clients
and web servers.
Understanding them is important for network troubleshooting and
SOC investigations.
</p>

<hr>

<h2>12.1 HTTP Fundamentals</h2>

<p>
<strong>HTTP = Hypertext Transfer Protocol</strong>
</p>

<p>
HTTP is a protocol used for communication between a
<strong>client</strong> and a <strong>web server</strong>.
</p>

<p>
For example, when you open a website, your browser communicates with
the web server using HTTP or HTTPS.
</p>

<pre>
Browser → Web Server
</pre>

<p>
HTTP does not provide encryption by itself.
</p>

<p>
<strong>Simple meaning:</strong><br>
HTTP = Rules used for communication between a web client and web server.
</p>

<hr>

<h2>12.2 HTTP Request</h2>

<p>
An <strong>HTTP request</strong> is sent by the client when it wants
something from the web server.
</p>

<pre>
Browser → Request → Web Server
</pre>

<p>A request can contain:</p>

<ul>
  <li>HTTP Method</li>
  <li>URL / Path</li>
  <li>Headers</li>
  <li>Request Body (when applicable)</li>
</ul>

<h3>Example</h3>

<pre>
GET /index.html HTTP/1.1
Host: example.com
</pre>

<hr>

<h2>12.3 HTTP Response</h2>

<p>
An <strong>HTTP response</strong> is the server's reply to the client.
</p>

<pre>
Web Server → Response → Browser
</pre>

<p>A response can contain:</p>

<ul>
  <li>Status Code</li>
  <li>Headers</li>
  <li>Response Body</li>
</ul>

<h3>Example</h3>

<pre>
HTTP/1.1 200 OK
Content-Type: text/html
</pre>

<p>
The response body may contain the actual webpage content.
</p>

<hr>

<h2>12.4 HTTP Methods</h2>

<p>
HTTP methods tell the server what the client wants to do with a resource.
</p>

<ul>
  <li><strong>GET</strong> — Retrieve data</li>
  <li><strong>POST</strong> — Send data</li>
  <li><strong>PUT</strong> — Replace or update a resource</li>
  <li><strong>PATCH</strong> — Partially update a resource</li>
  <li><strong>DELETE</strong> — Delete a resource</li>
</ul>

<p>
For SOC L1, <strong>GET</strong> and <strong>POST</strong> are especially
important because they are frequently seen in web traffic.
</p>

<hr>

<h2>12.5 GET</h2>

<p>
<strong>GET</strong> is commonly used to request or retrieve information
from a server.
</p>

<pre>
GET /products HTTP/1.1
</pre>

<p>
The server may return a list of products.
</p>

<p>
GET requests can also contain parameters in the URL.
</p>

<pre>
/search?q=laptop
</pre>

<hr>

<h2>12.6 POST</h2>

<p>
<strong>POST</strong> is commonly used when the client needs to send
data to the server.
</p>

<p>Examples include:</p>

<ul>
  <li>Login credentials</li>
  <li>Form submissions</li>
  <li>Creating data</li>
  <li>Uploading information</li>
</ul>

<h3>Example</h3>

<pre>
POST /login HTTP/1.1
</pre>

<p>
The submitted data is commonly carried in the request body.
</p>

<p>
<strong>GET → Usually retrieves data</strong><br>
<strong>POST → Usually sends data</strong>
</p>

<hr>

<h2>12.7 HTTP Headers</h2>

<p>
<strong>HTTP headers</strong> contain additional information about
a request or response.
</p>

<h3>Example</h3>

<pre>
Host: example.com
User-Agent: Mozilla/5.0
Content-Type: application/json
</pre>

<p>Headers can provide information about:</p>

<ul>
  <li>Host</li>
  <li>Browser / Client</li>
  <li>Content Type</li>
  <li>Authentication</li>
  <li>Cookies</li>
  <li>Caching</li>
  <li>Server behavior</li>
</ul>

<p>
Headers are very useful when analyzing web traffic.
</p>

<hr>

<h2>12.8 HTTP Status Codes</h2>

<p>
HTTP status codes tell the client what happened with the request.
</p>

<h3>2xx — Success</h3>

<pre>
200 OK
201 Created
</pre>

<p>
The request was successfully processed.
</p>

<h3>3xx — Redirection</h3>

<pre>
301 Moved Permanently
302 Found
</pre>

<p>
The client is being redirected or referred somewhere else.
</p>

<h3>4xx — Client Error</h3>

<pre>
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
</pre>

<p>
There is a problem with the request or access.
</p>

<h3>5xx — Server Error</h3>

<pre>
500 Internal Server Error
502 Bad Gateway
503 Service Unavailable
</pre>

<p>
The server or an upstream service encountered a problem.
</p>

<hr>

<h2>12.9 Cookies</h2>

<p>
A <strong>cookie</strong> is small data that a website stores in
the user's browser.
</p>

<p>Cookies can be used for:</p>

<ul>
  <li>Login state</li>
  <li>User preferences</li>
  <li>Tracking</li>
  <li>Shopping carts</li>
</ul>

<p>
A cookie can contain a session identifier that helps a website
recognize the user.
</p>

<p>
<strong>SOC relevance:</strong>
Suspicious or stolen cookies can sometimes be associated with
account or session abuse.
</p>

<hr>

<h2>12.10 Sessions</h2>

<p>
A <strong>session</strong> represents a user's ongoing interaction
with a web application.
</p>

<pre>
Login → Session Created → User Accesses Website
</pre>

<p>
The server needs a way to recognize that subsequent requests belong
to the authenticated user.
</p>

<p>
A <strong>session ID</strong> is commonly used for this purpose.
</p>

<pre>
Session ID = abc123...
</pre>

<p>
The exact implementation depends on the application.
</p>

<hr>

<h2>12.11 User-Agent</h2>

<p>
The <strong>User-Agent</strong> HTTP header provides information about
the client making the request.
</p>

<h3>Example</h3>

<pre>
User-Agent: Mozilla/5.0
</pre>

<p>It can provide information about:</p>

<ul>
  <li>Browser</li>
  <li>Operating System</li>
  <li>Client Software</li>
</ul>

<h3>SOC Relevance</h3>

<p>
An unusual User-Agent can sometimes be a useful investigation clue.
</p>

<p>
A normal browser may use a common browser User-Agent, while automated
tools or malware may use unusual or custom values.
</p>

<p>
<strong>
User-Agent is evidence, not proof of malicious activity by itself.
</strong>
</p>

<hr>

<h2>12.13 Web Server Communication</h2>

<p>
A web application normally involves communication between a
<strong>client</strong> and a <strong>web server</strong>.
</p>

<p>The client could be:</p>

<ul>
  <li>Web Browser</li>
  <li>Mobile Application</li>
  <li>API Client</li>
</ul>

<p>
The server processes the request and sends a response.
</p>

<pre>
Client
  ↓
HTTP / HTTPS Request
  ↓
Web Server
  ↓
HTTP / HTTPS Response
  ↓
Client
</pre>

<p>
The web server may also communicate with backend components such as:
</p>

<ul>
  <li>Application Server</li>
  <li>Database</li>
  <li>Authentication Service</li>
</ul>

<p>
A modern website is therefore often made up of multiple backend
components rather than a single server.
</p>

<hr>

<h2>12.14 HTTP vs HTTPS</h2>

<h3>HTTP</h3>

<p>
HTTP does not provide encryption by itself.
</p>

<pre>
HTTP
 ↓
Web Communication
</pre>

<h3>HTTPS</h3>

<p>
<strong>HTTPS = HTTP over TLS</strong>
</p>

<p>
HTTPS protects HTTP communication using TLS encryption.
</p>

<pre>
HTTPS
  ↓
TLS Protection
  ↓
HTTP Communication
</pre>

<p>HTTPS helps provide:</p>

<ul>
  <li><strong>Confidentiality</strong> — Helps prevent others from reading the data</li>
  <li><strong>Integrity</strong> — Helps detect unauthorized modification</li>
  <li><strong>Authentication</strong> — TLS certificates help authenticate the server</li>
</ul>

<h3>Common Ports</h3>

<table>
  <thead>
    <tr>
      <th>Protocol</th>
      <th>Common Port</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>HTTP</td>
      <td>80</td>
    </tr>
    <tr>
      <td>HTTPS</td>
      <td>443</td>
    </tr>
  </tbody>
</table>

<p>
<strong>HTTP → Web communication without TLS protection</strong><br>
<strong>HTTPS → HTTP protected by TLS</strong>
</p>

<h2>🎯 SOC L1 Connection</h2>
<p>
HTTP and HTTPS data can provide valuable information during security
investigations.
</p>

<p>Depending on the available logs or monitoring tools, an analyst may see:</p>

<ul>
  <li>Source IP</li>
  <li>Destination IP</li>
  <li>URL / Domain</li>
  <li>HTTP Method</li>
  <li>Status Code</li>
  <li>User-Agent</li>
  <li>Request / Response details</li>
  <li>Cookies or session-related information, where visible</li>
  <li>Request timing</li>
</ul>

<h3>Example Web Log</h3>

<pre>
Source:      10.10.1.25
Destination: example.com
Method:      GET
Path:        /login
Status:      200
User-Agent:  Mozilla/5.0
</pre>

<p>
This helps the analyst understand
<strong>who communicated with which web service, what they requested,
and how the server responded.</strong>
</p>
