<h2>1. Routing</h2>

<p>
<strong>Routing</strong> is the process of deciding where network traffic should go
to reach its destination.
</p>

<p>
A <strong>router</strong> mainly performs this job by checking the destination IP
and selecting an appropriate path.
</p>

<p>
<strong>Simple meaning:</strong>
</p>

<blockquote>
Routing = Deciding where packets should go.
</blockquote>

<hr>

<h2>2. Routing Table</h2>

<p>
A <strong>routing table</strong> contains information that a router uses to
decide where packets should be forwarded.
</p>

<table>
  <thead>
    <tr>
      <th>Destination Network</th>
      <th>Next Hop / Interface</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>192.168.1.0/24</td>
      <td>Local</td>
    </tr>
    <tr>
      <td>10.10.20.0/24</td>
      <td>192.168.1.1</td>
    </tr>
    <tr>
      <td>0.0.0.0/0</td>
      <td>ISP</td>
    </tr>
  </tbody>
</table>

<p>
When a packet arrives, the router checks the destination IP and looks for the
<strong>best matching route</strong>.
</p>

<hr>

<h2>3. Static &amp; Dynamic Routing</h2>

<h3>Static Routing</h3>

<p>
A <strong>static route</strong> is manually configured by a network administrator.
</p>

<p><strong>Advantages:</strong></p>

<ul>
  <li>Simple for small networks</li>
  <li>Predictable</li>
  <li>No routing protocol required</li>
</ul>

<p><strong>Disadvantage:</strong></p>

<p>
Routes must be updated manually when the network changes.
</p>

<h3>Dynamic Routing</h3>

<p>
With <strong>dynamic routing</strong>, routers use routing protocols to learn
routes automatically.
</p>

<p>Examples:</p>

<ul>
  <li>OSPF</li>
  <li>EIGRP</li>
  <li>BGP</li>
  <li>RIP</li>
</ul>

<p>
Dynamic routing is useful for larger networks where manually configuring every
route would be difficult.
</p>

<p>
<strong>Static = Manually configured</strong><br>
<strong>Dynamic = Routes learned automatically</strong>
</p>

<hr>

<h2>4. Default Route</h2>

<p>
A <strong>default route</strong> is used when the router does not have a more
specific route for the destination.
</p>

<p>It is commonly written as:</p>

<pre>
0.0.0.0/0
</pre>

<p>
It basically means:
</p>

<blockquote>
If I don't know where this destination belongs, send it this way.
</blockquote>

<p>
A home router commonly uses a default route toward the ISP for Internet traffic.
</p>

<hr>

<h2>5. Next Hop</h2>

<p>
The <strong>next hop</strong> is the next router or network device to which a
packet should be forwarded.
</p>

<p><strong>Example:</strong></p>

<pre>
Destination: 10.20.30.0/24
Next Hop:    192.168.1.1
</pre>

<p>
This means:
</p>

<blockquote>
To reach 10.20.30.0/24, send the packet to 192.168.1.1.
</blockquote>

<p>
The next hop is <strong>not necessarily the final destination</strong>.
It is simply the next device in the path.
</p>

<hr>

<h2>6. Routing Between Networks</h2>

<p>
Routing allows devices on <strong>different networks</strong> to communicate.
</p>

<p><strong>Example:</strong></p>

<pre>
Network A: 192.168.1.0/24

Network B: 192.168.2.0/24
</pre>

<p>
These are two different IP networks.
A router or Layer 3 device can connect them and make communication possible.
</p>

<p>
<strong>Layer 2 switch → Mainly connects devices within a LAN</strong><br>
<strong>Router → Connects different networks</strong>
</p>

<hr>

<h2>7. Layer 3 Switching</h2>

<p>
A traditional switch mainly works at <strong>Layer 2</strong> using MAC addresses.
</p>

<p>
A <strong>Layer 3 switch</strong> can also perform routing using IP addresses.
</p>

<p>
This makes Layer 3 switches useful inside larger networks.
</p>

<p>
For example, a company may have separate networks or VLANs for:
</p>

<ul>
  <li>HR</li>
  <li>IT</li>
  <li>Finance</li>
  <li>Guest</li>
</ul>

<p>
A Layer 3 switch can route traffic between these networks when the network
configuration allows it.
</p>

<p>
<strong>Layer 2 Switch → MAC-based switching</strong><br>
<strong>Layer 3 Switch → MAC switching + IP routing</strong>
</p>

<hr>

<h2>8. NAT</h2>

<p>
<strong>NAT = Network Address Translation</strong>
</p>

<p>
NAT changes IP address information as traffic passes between networks.
</p>

<p>
One common use is allowing devices with <strong>private IP addresses</strong>
to access the Internet using a public IP.
</p>

<p><strong>Example:</strong></p>

<pre>
Private IP → Public IP

192.168.1.10 → Public IP
</pre>

<p>
NAT is commonly performed by a router or firewall.
</p>

<p><strong>Why NAT is used:</strong></p>

<ul>
  <li>Allows private devices to access the Internet</li>
  <li>Conserves public IPv4 addresses</li>
  <li>Helps keep internal addressing from being directly exposed</li>
</ul>

<p>
<strong>Important:</strong> NAT is not the same as a firewall.
NAT translates addresses, while a firewall controls traffic based on security
rules.
</p>

<hr>

<h2>9. PAT</h2>

<p>
<strong>PAT = Port Address Translation</strong>
</p>

<p>
PAT is a form of NAT that allows <strong>many private devices to share one
public IP address</strong> by using different port numbers.
</p>

<p><strong>Example:</strong></p>

<pre>
192.168.1.10:5000
192.168.1.11:5001
192.168.1.12:5002
</pre>

<p>
The router keeps track of the different connections using port information.
</p>

<p>
This is extremely common in home and office networks.
</p>

<p>
<strong>NAT → Translates IP addresses</strong><br>
<strong>PAT → Translates addresses + uses ports to distinguish connections</strong>
</p>

<hr>

<h2>10. Network Path</h2>

<p>
A <strong>network path</strong> is the series of network devices and connections
that traffic uses to reach a destination.
</p>

<p>
Traffic may pass through multiple:
</p>

<ul>
  <li>Switches</li>
  <li>Routers</li>
  <li>Firewalls</li>
  <li>ISP networks</li>
</ul>

<p>
The exact path can change depending on routing decisions and network conditions.
</p>

<h3>SOC Relevance</h3>

<p>
Understanding the network path helps during investigations to determine:
</p>

<ul>
  <li>Where traffic came from</li>
  <li>Where it is going</li>
  <li>Which network devices it crossed</li>
  <li>Where a connection may have been blocked or failed</li>
</ul>

<hr>

<h2>11. Traceroute</h2>

<p>
<strong>Traceroute</strong> is a network troubleshooting tool used to identify
the <strong>routers or hops between your device and a destination</strong>.
</p>

<p>Linux:</p>

<pre>
traceroute 8.8.8.8
</pre>

<p>Windows:</p>

<pre>
tracert 8.8.8.8
</pre>

<p>
It may show several hops before reaching the destination.
Each hop represents a network device or router that responded along the path.
</p>

<p><strong>Traceroute can help identify:</strong></p>

<ul>
  <li>Where connectivity is failing</li>
  <li>How traffic is reaching a destination</li>
  <li>Network delays</li>
  <li>Possible routing problems</li>
</ul>
