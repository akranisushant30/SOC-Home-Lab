<h2>1. DHCP Basics</h2>

<p>
<strong>DHCP = Dynamic Host Configuration Protocol</strong>
</p>

<p>
DHCP automatically provides network settings to a device when it joins a network.
</p>

<p>DHCP can provide:</p>

<ul>
  <li>IP Address</li>
  <li>Subnet Mask</li>
  <li>Default Gateway</li>
  <li>DNS Server</li>
</ul>

<p>
<strong>Simple meaning:</strong>
DHCP automatically gives a device the network information it needs to communicate.
</p>

<p>
For example, when your laptop connects to Wi-Fi, it usually gets its IP
configuration through DHCP.
</p>

<hr>

<h2>2. DHCP DORA</h2>

<p>
<strong>DORA</strong> is the four-step DHCP process used when a client needs
an IP configuration.
</p>

<ul>
  <li><strong>D — Discover</strong></li>
  <li><strong>O — Offer</strong></li>
  <li><strong>R — Request</strong></li>
  <li><strong>A — Acknowledge</strong></li>
</ul>

<h3>Discover</h3>

<p>
The client looks for an available DHCP server.
</p>

<h3>Offer</h3>

<p>
The DHCP server offers an IP address and network configuration.
</p>

<h3>Request</h3>

<p>
The client requests the offered configuration.
</p>

<h3>Acknowledge</h3>

<p>
The DHCP server confirms the assignment.
</p>

<p>
<strong>DORA = The basic process used to obtain a DHCP lease.</strong>
</p>

<hr>

<h2>3. DHCP Lease</h2>

<p>
A <strong>DHCP lease</strong> is the period for which a device is allowed
to use a particular IP configuration.
</p>

<pre>
IP Address: 192.168.1.20
Lease Time: 8 hours
</pre>

<p>
The device can use that IP during the lease period.
</p>

<p>
Before the lease expires, the client normally tries to renew it.
</p>

<p>
Leases allow DHCP servers to reuse IP addresses when devices leave the network.
</p>

<hr>

<h2>4. DHCP Server &amp; Client</h2>

<h3>DHCP Server</h3>

<p>
The <strong>DHCP server</strong> manages IP addresses and provides network
configuration to clients.
</p>

<p>
It maintains a pool of available addresses.
</p>

<h3>DHCP Client</h3>

<p>
The <strong>DHCP client</strong> is the device requesting network configuration.
</p>

<p>Examples:</p>

<ul>
  <li>Laptop</li>
  <li>Desktop</li>
  <li>Phone</li>
  <li>Printer</li>
  <li>Virtual Machine</li>
</ul>

<p>
<strong>DHCP Server = Gives network configuration</strong><br>
<strong>DHCP Client = Requests network configuration</strong>
</p>

<hr>

<h2>5. DHCP Scope</h2>

<p>
A <strong>DHCP scope</strong> defines the range of IP addresses that a DHCP
server can assign to clients.
</p>

<pre>
Network:
192.168.1.0/24

DHCP Scope:
192.168.1.100
      ↓
192.168.1.200
</pre>

<p>
The server can assign addresses from this configured range.
</p>

<p>A scope can also contain settings such as:</p>

<ul>
  <li>Default Gateway</li>
  <li>DNS Server</li>
  <li>Lease Duration</li>
</ul>

<hr>

<h2>6. IP Assignment</h2>

<p>
DHCP automatically assigns an available IP address to a client.
</p>

<pre>
Laptop  → 192.168.1.105
Phone   → 192.168.1.106
Printer → 192.168.1.107
</pre>

<p>
The DHCP server keeps track of assigned addresses so it can avoid assigning
the same address to two clients at the same time.
</p>

<hr>

<h2>7. Gateway Assignment</h2>

<p>
DHCP can tell a device which <strong>default gateway</strong> it should use.
</p>

<pre>
Device IP:
192.168.1.105

Default Gateway:
192.168.1.1
</pre>

<p>
The device uses the default gateway when it needs to communicate with
destinations outside its local network.
</p>

<p>
<strong>Simple meaning:</strong>
DHCP can tell your device which router it should use to reach other networks.
</p>

<hr>

<h2>8. DNS Assignment</h2>

<p>
DHCP can provide the <strong>DNS server address</strong> that a device should use.
</p>

<pre>
DNS Server:
192.168.1.1
</pre>

<p>
The device then uses that DNS server to resolve domain names.
</p>

<pre>
google.com → IP Address
</pre>

<p>
DHCP does not perform DNS resolution itself.
</p>

<p>
<strong>DHCP tells the device which DNS server to use.</strong>
</p>

<hr>

<h2>9. Static vs Dynamic IP</h2>

<h3>Dynamic IP</h3>

<p>
A <strong>dynamic IP</strong> is automatically assigned by DHCP.
</p>

<pre>
Laptop → DHCP → 192.168.1.105
</pre>

<p>
The address can change over time.
</p>

<p>Commonly used for:</p>

<ul>
  <li>Laptops</li>
  <li>Phones</li>
  <li>Employee devices</li>
  <li>Guest devices</li>
</ul>

<h3>Static IP</h3>

<p>
A <strong>static IP</strong> is manually configured or deliberately reserved
so that a device keeps a predictable address.
</p>

<p>Commonly used for:</p>

<ul>
  <li>Servers</li>
  <li>Network devices</li>
  <li>Printers</li>
  <li>Security appliances</li>
</ul>

<pre>
Server:
192.168.1.10
</pre>

<h3>Dynamic vs Static</h3>

<table>
  <thead>
    <tr>
      <th>Dynamic IP</th>
      <th>Static IP</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Usually assigned by DHCP</td>
      <td>Manually configured or reserved</td>
    </tr>
    <tr>
      <td>Can change</td>
      <td>Intended to remain consistent</td>
    </tr>
    <tr>
      <td>Good for normal client devices</td>
      <td>Useful for servers and network devices</td>
    </tr>
  </tbody>
</table>

<h2>SOC L1 Connection</h2>

<p>
DHCP is useful during investigations because it can help answer:
</p>

<blockquote>
Which device had this IP address at a particular time?
</blockquote>

<p>
For example, if a SIEM alert shows:
</p>

<pre>
192.168.1.105
</pre>

<p>
a SOC analyst may need DHCP logs to determine which device or user was using
that IP at the time of the event.
</p>

<p>
This makes DHCP logs valuable for
<strong>IP-to-device correlation and incident investigation.</strong>
</p>
