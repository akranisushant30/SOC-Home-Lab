<h2>1. DNS — Domain Name System</h2>

<p>
<strong>DNS</strong> converts domain names into IP addresses.
</p>

<p>
For example, users remember <code>google.com</code>, while computers communicate
using IP addresses.
</p>

<pre>
google.com → IP Address
</pre>

<p>
DNS works like the <strong>Internet's phonebook</strong>.
</p>

<p>
<strong>Port:</strong> 53 — UDP/TCP
</p>

<p>
<strong>SOC Importance:</strong> Unusual DNS queries can be useful indicators
during malware or DNS tunneling investigations.
</p>

<hr>

<h2>2. DHCP — Dynamic Host Configuration Protocol</h2>

<p>
<strong>DHCP</strong> automatically provides network configuration to devices.
</p>

<p>It can provide:</p>

<ul>
  <li>IP address</li>
  <li>Subnet mask</li>
  <li>Default gateway</li>
  <li>DNS server</li>
</ul>

<p>
<strong>Ports:</strong> 67/68 — UDP
</p>

<p>
<strong>Simple meaning:</strong> DHCP automatically gives a device its network configuration.
</p>

<hr>

<h2>3. HTTP — Hypertext Transfer Protocol</h2>

<p>
<strong>HTTP</strong> is used to transfer web content between a client and a web server.
</p>

<pre>
Browser → Web Server
</pre>

<p>
<strong>Port:</strong> 80 — TCP
</p>

<p>
HTTP traffic is <strong>not encrypted by itself</strong>.
</p>

<hr>

<h2>4. HTTPS — Hypertext Transfer Protocol Secure</h2>

<p>
<strong>HTTPS</strong> is HTTP protected using <strong>TLS encryption</strong>.
</p>

<p>
It helps protect data exchanged between the client and server from being easily
read or modified in transit.
</p>

<pre>
https://example.com
</pre>

<p>
<strong>Port:</strong> 443 — TCP
</p>

<p>
<strong>SOC Importance:</strong> HTTPS connections are commonly visible in logs,
but the encrypted payload normally cannot be read directly without appropriate
inspection or decryption.
</p>

<hr>

<h2>5. FTP — File Transfer Protocol</h2>

<p>
<strong>FTP</strong> is used to transfer files between systems.
</p>

<p>It can be used to:</p>

<ul>
  <li>Upload files</li>
  <li>Download files</li>
  <li>Browse directories</li>
</ul>

<p><strong>Ports:</strong></p>

<pre>
21 → Control
20 → Data (traditional active mode)
</pre>

<p>
FTP does <strong>not provide encryption by default</strong>.
</p>

<p>
<strong>SOC Importance:</strong> FTP can be important when investigating file
transfers or possible data exfiltration.
</p>

<hr>

<h2>6. SFTP — SSH File Transfer Protocol</h2>

<p>
<strong>SFTP</strong> provides secure file transfer over SSH.
</p>

<p>It allows users to:</p>

<ul>
  <li>Upload files</li>
  <li>Download files</li>
  <li>Manage files and directories</li>
</ul>

<p>
<strong>Port:</strong> 22 — TCP
</p>

<p>
<strong>FTP → Not encrypted by default</strong><br>
<strong>SFTP → Encrypted through SSH</strong>
</p>

<p>
SFTP is a different protocol from FTP; it operates over SSH.
</p>

<hr>

<h2>7. SSH — Secure Shell</h2>

<p>
<strong>SSH</strong> provides secure remote access to another computer.
</p>

<pre>
ssh user@192.168.1.10
</pre>

<p>SSH can be used for:</p>

<ul>
  <li>Remote administration</li>
  <li>Running commands remotely</li>
  <li>Secure file transfer</li>
  <li>Tunneling</li>
</ul>

<p>
<strong>Port:</strong> 22 — TCP
</p>

<p>
<strong>SOC Importance:</strong> SSH is important when investigating brute-force
attacks, unauthorized remote access, and suspicious administration activity.
</p>

<hr>

<h2>8. Telnet</h2>

<p>
<strong>Telnet</strong> provides remote command-line access, similar to SSH.
</p>

<p>
However, Telnet sends communication <strong>without encryption by default</strong>.
</p>

<p>
<strong>Port:</strong> 23 — TCP
</p>

<pre>
Telnet → Unencrypted
SSH    → Encrypted
</pre>

<p>
SSH is preferred for secure remote administration.
</p>

<hr>

<h2>9. SMTP — Simple Mail Transfer Protocol</h2>

<p>
<strong>SMTP</strong> is mainly used to send and relay email.
</p>

<p>
When an email is sent, SMTP is involved in transferring the message toward
the recipient's mail server.
</p>

<p><strong>Common ports:</strong></p>

<pre>
25  → SMTP Relay
587 → Message Submission
465 → SMTP over implicit TLS
</pre>

<p>
<strong>SOC Importance:</strong> SMTP is important when investigating phishing,
malicious email delivery, and suspicious mail activity.
</p>

<hr>

<h2>10. POP3 — Post Office Protocol 3</h2>

<p>
<strong>POP3</strong> is used by an email client to retrieve email from a mail server.
</p>

<p>
Traditional POP3 generally downloads messages to the client.
</p>

<p><strong>Ports:</strong></p>

<pre>
110 → POP3
995 → POP3 over TLS
</pre>

<p>
<strong>Simple meaning:</strong> POP3 mainly downloads email from the server.
</p>

<hr>

<h2>11. IMAP — Internet Message Access Protocol</h2>

<p>
<strong>IMAP</strong> is used to access email while keeping the mailbox
synchronized with the mail server.
</p>

<p>
The same mailbox can be accessed from:</p>

<ul>
  <li>Laptop</li>
  <li>Phone</li>
  <li>Tablet</li>
</ul>

<p><strong>Ports:</strong></p>

<pre>
143 → IMAP
993 → IMAP over TLS
</pre>

<h3>POP3 vs IMAP</h3>

<p>
<strong>POP3 → Mainly downloads mail</strong><br>
<strong>IMAP → Keeps mail synchronized with the server</strong>
</p>

<hr>

<h2>12. SMB — Server Message Block</h2>

<p>
<strong>SMB</strong> is used for sharing files, folders, printers, and other
resources across a network.
</p>

<p>
It is very common in <strong>Windows environments</strong>.
</p>

<pre>
\\SERVER\SharedFolder
</pre>

<p>
<strong>Port:</strong> 445 — TCP
</p>

<p>
<strong>SOC Importance:</strong> SMB is important in Windows security
investigations because attackers may abuse it for lateral movement,
remote access, and file sharing.
</p>

<hr>

<h2>13. LDAP — Lightweight Directory Access Protocol</h2>

<p>
<strong>LDAP</strong> is used to access and manage directory information.
</p>

<p>In enterprise environments, it can be used to query:</p>

<ul>
  <li>Users</li>
  <li>Groups</li>
  <li>Computers</li>
  <li>Organizational information</li>
</ul>

<p>
<strong>Port:</strong> 389 — TCP/UDP
</p>

<p>
Secure LDAP commonly uses:
</p>

<pre>
636 → LDAPS
</pre>

<p>
<strong>SOC Importance:</strong> LDAP activity can be relevant when investigating
suspicious directory queries or account-related activity.
</p>

<hr>

<h2>14. RDP — Remote Desktop Protocol</h2>

<p>
<strong>RDP</strong> allows users to remotely access a Windows desktop.
</p>

<p>
For example, an administrator can remotely connect to a Windows server
and interact with its desktop.
</p>

<p>
<strong>Port:</strong> 3389 — TCP/UDP
</p>

<p><strong>SOC Importance:</strong> RDP is important when investigating:</p>

<ul>
  <li>Brute-force attempts</li>
  <li>Unauthorized remote access</li>
  <li>Lateral movement</li>
</ul>

<hr>

<h2>15. ICMP — Internet Control Message Protocol</h2>

<p>
<strong>ICMP</strong> is used for network diagnostics and control/error messages.
</p>

<p>
A common example is:
</p>

<pre>
ping 8.8.8.8
</pre>

<p>
Ping uses ICMP Echo Request and Echo Reply messages.
</p>

<p>
<strong>Important:</strong> ICMP does not use TCP or UDP ports because it is
a network-layer protocol.
</p>

<p>
<strong>SOC Importance:</strong> ICMP can be useful when investigating network
discovery, connectivity, or unusual ICMP traffic.
</p>

<hr>

<h2>16. NTP — Network Time Protocol</h2>

<p>
<strong>NTP</strong> synchronizes the clocks of computers and network devices.
</p>

<p>
Correct time is extremely important because security logs depend on accurate
timestamps.
</p>

<p>
<strong>Port:</strong> 123 — UDP
</p>

<p>
For SOC analysts, accurate time helps correlate events from:
</p>

<ul>
  <li>Windows</li>
  <li>Linux</li>
  <li>Firewalls</li>
  <li>IDS/IPS</li>
  <li>SIEM</li>
</ul>

<p>
Incorrect system times can make building an accurate attack timeline much harder.
</p>

<h2>SOC L1 Connection</h2>

<p>
When analyzing network activity, pay attention to the
<strong>Source IP, Destination IP, Port, and Protocol</strong>.
</p>

<pre>
192.168.1.50 → 192.168.1.10:22

Protocol: TCP
Service: SSH
Purpose: Remote Access
</pre>

<pre>
192.168.1.50 → 192.168.1.10:445

Protocol: TCP
Service: SMB
Purpose: Windows File/Resource Sharing
</pre>

<pre>
192.168.1.50 → 8.8.8.8:53

Protocol: UDP
Service: DNS
Purpose: Name Resolution
</pre>

<p>
Understanding <strong>IP + Port + Protocol</strong> helps a SOC analyst
identify what type of network activity is taking place.
</p>
