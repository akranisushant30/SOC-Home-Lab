<h1>Chapter 16 — Network Architecture</h1>
<p>
Understanding how an organization's network is structured,
segmented, and monitored from a SOC L1 perspective.
</p>

</div>

<hr>

<h2>1. Internal & External Networks</h2>

<h3>Internal Network</h3>

<p>
An <strong>internal network</strong> is the private network used inside an organization.
It contains systems and devices that are part of the company's environment.
</p>

<p><strong>Examples:</strong></p>

<ul>
<li>Employee computers</li>
<li>Internal servers</li>
<li>Printers</li>
<li>Internal applications</li>
</ul>

<pre>
Employee PC
     |
Internal Network
     |
  Firewall
     |
  Internet
</pre>

<h3>External Network</h3>

<p>
An <strong>external network</strong> is outside the organization's network,
mainly the Internet.
</p>

<h3>🛡️ SOC L1 Focus</h3>

<p>A SOC Analyst should understand whether traffic is:</p>

<ul>
<li>Internal → Internal</li>
<li>Internal → External</li>
<li>External → Internal</li>
</ul>

<p>
For example, if an internal workstation suddenly communicates with an
unknown external IP address, the activity may require investigation.
</p>

<hr>

<h2>2. DMZ</h2>

<p>
<strong>DMZ (Demilitarized Zone)</strong> is a separate network used for
systems that need to be accessible from the Internet.
</p>

<p><strong>Common examples:</strong></p>

<ul>
<li>Web servers</li>
<li>Mail servers</li>
<li>Public DNS servers</li>
</ul>

<pre>
                INTERNET
                    |
                 Firewall
                    |
                   DMZ
             +------+------+
             |             |
        Web Server     Mail Server
                    |
             Internal Network
</pre>

<h3>🛡️ SOC L1 Focus</h3>

<p>Important traffic includes:</p>

<pre>
Internet → DMZ
DMZ → Internal
DMZ → Internet
</pre>

<p>
<strong>DMZ → Internal</strong> traffic is especially important.
If a public-facing server is compromised, an attacker may try to use it
as a starting point to attack internal systems.
</p>

<hr>

<h2>3. User Network</h2>

<p>
The <strong>user network</strong> contains normal employee devices used
for daily business activities.
</p>

<p><strong>Examples:</strong></p>

<ul>
<li>Laptops</li>
<li>Desktops</li>
<li>Workstations</li>
<li>Corporate endpoints</li>
</ul>

<pre>
Employee PC
     |
User Network
     |
 Firewall
     |
 Internet
</pre>

<h3>🛡️ SOC L1 Focus</h3>

<p>A compromised workstation may:</p>

<ul>
<li>Scan multiple systems</li>
<li>Connect to unusual ports</li>
<li>Contact suspicious external IP addresses</li>
<li>Upload unusually large amounts of data</li>
</ul>

<p>
These behaviors may indicate malware, scanning, lateral movement,
or data exfiltration.
</p>

<hr>

<h2>4. Server Network</h2>

<p>
The <strong>server network</strong> contains important systems that provide
services to users and applications.
</p>

<p><strong>Examples:</strong></p>

<ul>
<li>Web servers</li>
<li>Database servers</li>
<li>File servers</li>
<li>Application servers</li>
<li>Domain Controllers</li>
</ul>

<pre>
User Network
     |
  Firewall
     |
Server Network
</pre>

<h3>🛡️ SOC L1 Focus</h3>

<p>Normal communication:</p>

<pre>
User PC → Application Server
</pre>

<p>Potentially suspicious communication:</p>

<pre>
User PC → Many Servers
</pre>

<p>
A workstation connecting to many servers in a short period may indicate
network scanning or lateral movement.
</p>

<hr>

<h2>5. Guest Network</h2>

<p>
The <strong>guest network</strong> is designed for visitors and their devices.
It should normally be isolated from the organization's internal network.
</p>

<pre>
Guest Device
     |
Guest Wi-Fi
     |
 Internet
</pre>

<table>
<thead>
<tr>
<th>Traffic</th>
<th>Expected?</th>
</tr>
</thead>
<tbody>
<tr>
<td>Guest → Internet</td>
<td>✅ Yes</td>
</tr>
<tr>
<td>Guest → Internal Server</td>
<td>❌ Normally No</td>
</tr>
<tr>
<td>Guest → Employee PC</td>
<td>❌ Normally No</td>
</tr>
<tr>
<td>Guest → Management Network</td>
<td>❌ Normally No</td>
</tr>
</tbody>
</table>

<h3>🛡️ SOC L1 Focus</h3>

<p>
A guest device attempting to access internal resources may indicate
misconfiguration, unauthorized access, or malicious activity.
</p>

<hr>

<h2>6. Management Network</h2>

<p>
The <strong>management network</strong> is used to administer and manage
network infrastructure and important systems.
</p>

<p><strong>Examples:</strong></p>

<ul>
<li>Firewalls</li>
<li>Switches</li>
<li>Routers</li>
<li>Servers</li>
<li>Monitoring systems</li>
</ul>

<pre>
Administrator
      |
Management Network
      |
Network Devices
</pre>

<h3>🛡️ SOC L1 Focus</h3>

<p>
Management systems are high-value targets because controlling them may
give an attacker significant access to the environment.
</p>

<p>For example:</p>

<pre>
Employee PC
      |
Firewall Management Interface
</pre>

<p>
Unexpected access to management interfaces should be investigated.
</p>

<hr>

<h2>7. VLAN Segmentation</h2>

<p>
<strong>VLAN (Virtual Local Area Network)</strong> allows an organization
to logically separate devices into different networks.
</p>

<pre>
VLAN 10 → Users
VLAN 20 → Servers
VLAN 30 → Guests
VLAN 40 → Management
</pre>

<h3>Why VLAN Segmentation?</h3>

<ul>
<li>Network separation</li>
<li>Access control</li>
<li>Reduced attack surface</li>
<li>Better traffic management</li>
</ul>

<h3>🛡️ SOC L1 Focus</h3>

<p>
For a SOC Analyst, VLANs can be viewed as <strong>logical network boundaries</strong>.
</p>

<p>For example:</p>

<pre>
Guest VLAN → Management VLAN
</pre>

<p>
This type of communication should normally be restricted.
Unexpected VLAN-to-VLAN communication can be useful during investigation.
</p>

<hr>

<h2>8. Security Zones</h2>

<p>
A <strong>security zone</strong> is a network area that has its own
security rules and access controls.
</p>

<pre>
Internet
   |
External Zone
   |
DMZ Zone
   |
Internal Zone
   |
Management Zone
</pre>

<table>
<thead>
<tr>
<th>Traffic</th>
<th>Typical Policy</th>
</tr>
</thead>
<tbody>
<tr>
<td>Internet → DMZ</td>
<td>Specific traffic allowed</td>
</tr>
<tr>
<td>Internet → Internal</td>
<td>Usually blocked</td>
</tr>
<tr>
<td>Guest → Internal</td>
<td>Usually blocked</td>
</tr>
<tr>
<td>User → Server</td>
<td>Required services only</td>
</tr>
<tr>
<td>User → Management</td>
<td>Highly restricted</td>
</tr>
</tbody>
</table>

<h3>🛡️ SOC L1 Focus</h3>

<p>
When investigating an alert, identify:
</p>

<pre>
Source Zone → Destination Zone
</pre>

<p>
Understanding the source and destination zones provides important context
for deciding whether the traffic is normal or suspicious.
</p>

<hr>

<h2>9. East-West Traffic</h2>

<p>
<strong>East-West traffic</strong> means traffic between systems inside
the organization's network.
</p>

<p>Examples:</p>

<pre>
PC → Server
Server → Server
PC → PC
</pre>

<h3>🛡️ SOC L1 Focus</h3>

<p>
East-West traffic is important when detecting
<strong>lateral movement</strong>.
</p>

<p>Example attack path:</p>

<pre>
Compromised PC
      |
   Server 1
      |
   Server 2
      |
Domain Controller
</pre>

<p>
An attacker may compromise one endpoint and then attempt to move
through other internal systems.
</p>

<hr>

<h2>10. North-South Traffic</h2>

<p>
<strong>North-South traffic</strong> means traffic between the internal
network and external networks.
</p>

<p>Examples:</p>

<pre>
Internal PC → Internet
</pre>

<pre>
Internet → Company Server
</pre>

<h3>East-West vs North-South</h3>

<table>
<thead>
<tr>
<th>Traffic Type</th>
<th>Meaning</th>
<th>SOC Relevance</th>
</tr>
</thead>
<tbody>
<tr>
<td>East-West</td>
<td>Internal ↔ Internal</td>
<td>Lateral movement</td>
</tr>
<tr>
<td>North-South</td>
<td>Internal ↔ External</td>
<td>External attacks, C2, exfiltration</td>
</tr>
</tbody>
</table>

<h3>🛡️ SOC L1 Focus</h3>

<p>North-South traffic can help identify:</p>

<ul>
<li>External attacks</li>
<li>Command & Control (C2)</li>
<li>Data exfiltration</li>
<li>Internet scanning</li>
<li>Suspicious inbound connections</li>
</ul>

<hr>

<h2>11. Internet Perimeter</h2>

<p>
The <strong>Internet perimeter</strong> is the boundary between the
organization's network and the Internet.
</p>

<pre>
              INTERNET
                  |
              Edge Router
                  |
               Firewall
                  |
          +-------+-------+
          |               |
         DMZ       Internal Network
</pre>

<p>Common perimeter devices include:</p>

<ul>
<li>Firewalls</li>
<li>Edge routers</li>
<li>VPN gateways</li>
<li>Proxies</li>
</ul>

<h3>🛡️ SOC L1 Focus</h3>

<p>Perimeter logs can provide:</p>

<ul>
<li>Source IP</li>
<li>Destination IP</li>
<li>Port</li>
<li>Protocol</li>
<li>Allowed/Blocked status</li>
<li>Connection attempts</li>
</ul>

<p>Example:</p>

<pre>
External IP
     |
 Firewall
     |
  TCP 22
     |
  BLOCKED
</pre>

<p>
Repeated connection attempts may indicate scanning or brute-force activity.
</p>

<hr>

<h2>12. Proxy</h2>

<p>
A <strong>proxy</strong> acts as an intermediary between a client and
the Internet.
</p>

<h3>Without Proxy</h3>

<pre>
User → Website
</pre>

<h3>With Proxy</h3>

<pre>
User → Proxy → Website
</pre>

<p>A proxy can:</p>

<ul>
<li>Inspect web traffic</li>
<li>Filter websites</li>
<li>Block malicious destinations</li>
<li>Log user activity</li>
</ul>

<h3>🛡️ SOC L1 Focus</h3>

<p>Proxy logs may contain:</p>

<ul>
<li>Username</li>
<li>URL</li>
<li>Domain</li>
<li>Destination IP</li>
<li>Request</li>
<li>Allowed/Blocked status</li>
</ul>

<p>Example:</p>

<pre>
User
 |
Suspicious Domain
 |
Proxy
 |
BLOCKED
</pre>

<p>
The SOC can investigate why the user attempted to access the domain.
</p>

<hr>

<h2>13. Reverse Proxy</h2>

<p>
A <strong>reverse proxy</strong> sits in front of backend servers and
receives requests before they reach the application servers.
</p>

<h3>Normal Proxy</h3>

<pre>
User → Proxy → Internet
</pre>

<h3>Reverse Proxy</h3>

<pre>
Internet → Reverse Proxy → Web Server
</pre>

<p>A reverse proxy can provide:</p>

<ul>
<li>Access control</li>
<li>TLS termination</li>
<li>Security</li>
<li>Backend server protection</li>
<li>Traffic handling</li>
</ul>

<h3>🛡️ SOC L1 Focus</h3>

<p>Reverse proxy logs can help detect:</p>

<ul>
<li>Web scanning</li>
<li>SQL injection attempts</li>
<li>Suspicious URLs</li>
<li>Abnormal requests</li>
<li>Malicious User-Agents</li>
</ul>

<p>Example:</p>

<pre>
Attacker
   |
Reverse Proxy
   |
Web Server
</pre>

<p>
The reverse proxy can log suspicious requests before they reach
the backend application.
</p>

<hr>

<h2>14. Load Balancer</h2>

<p>
A <strong>load balancer</strong> distributes incoming traffic across
multiple servers.
</p>

<pre>
                    +→ Web Server 1
                    |
Internet → Load Balancer → Web Server 2
                    |
                    +→ Web Server 3
</pre>

<p>
This prevents all traffic from being sent to a single server and helps
applications handle large numbers of users.
</p>

<h3>🛡️ SOC L1 Focus</h3>

<p>Load balancer logs can help identify:</p>

<ul>
<li>Source IP</li>
<li>Requested application</li>
<li>Backend server</li>
<li>Request volume</li>
<li>HTTP status codes</li>
<li>Abnormal traffic</li>
</ul>

<p>
<strong>Important:</strong> The primary purpose of a load balancer is
traffic distribution. Modern load balancers may also provide security features.
</p>

<hr>

<h2>15. Zero Trust Basics</h2>

<p>
Traditional network security often assumed that users inside the network
could be trusted.
</p>

<p>
<strong>Zero Trust</strong> follows a different approach:
</p>

<blockquote>
Never automatically trust. Always verify.
</blockquote>

<pre>
User
 |
Verify Identity
 |
Verify Device
 |
Check Permissions
 |
Allow / Deny
</pre>

<h3>Zero Trust Principles</h3>

<ul>
<li>Verify identity</li>
<li>Verify the device</li>
<li>Use least privilege</li>
<li>Continuously verify access</li>
<li>Limit access to required resources</li>
</ul>

<h3>🛡️ SOC L1 Focus</h3>

<p>
An <strong>internal IP address does not automatically mean trusted</strong>.
</p>

<p>For example:</p>

<pre>
Internal PC → Internal Server
</pre>

<p>The SOC should still consider:</p>

<ul>
<li>Is the user authorized?</li>
<li>Is the device expected?</li>
<li>Is this normal behavior?</li>
<li>Is the requested resource appropriate?</li>
</ul>

<hr>

<h2>🎯 SOC L1 Investigation Mindset</h2>

<p>
Whenever you see a network alert, follow this basic thought process:
</p>

<pre>
Source
  ↓
Destination
  ↓
Network / VLAN
  ↓
Security Zone
  ↓
East-West or North-South?
  ↓
Expected or Suspicious?
  ↓
Investigate
</pre>

<h3>⭐ Key Takeaway</h3>

<blockquote>
A SOC L1 Analyst does not need to design the network.
The goal is to understand the network well enough to recognize abnormal
communication, identify important network zones, and investigate
suspicious traffic.
</blockquote>
