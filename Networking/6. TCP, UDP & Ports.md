<h2>1. Transport Layer</h2>

<p>
The <strong>Transport Layer (Layer 4)</strong> is responsible for
<strong>end-to-end communication between applications</strong>.
</p>

<p>It mainly uses:</p>

<ul>
  <li><strong>TCP</strong> → Reliable communication</li>
  <li><strong>UDP</strong> → Fast, connectionless communication</li>
</ul>

<p>
It also handles things like ports, segmentation, and reliability mechanisms.
</p>

<hr>

<h2>2. TCP</h2>

<p>
<strong>TCP = Transmission Control Protocol</strong>
</p>

<p>
TCP provides <strong>reliable and ordered communication</strong>.
</p>

<p>TCP makes sure that:</p>

<ul>
  <li>Data reaches the destination</li>
  <li>Data arrives in the correct order</li>
  <li>Lost data can be retransmitted</li>
  <li>Both sides know the connection status</li>
</ul>

<p>
TCP is <strong>connection-oriented</strong>, meaning a connection is established
before data is exchanged.
</p>

<p>Common examples:</p>

<ul>
  <li>HTTPS</li>
  <li>HTTP</li>
  <li>SSH</li>
  <li>FTP</li>
</ul>

<hr>

<h2>3. UDP</h2>

<p>
<strong>UDP = User Datagram Protocol</strong>
</p>

<p>
UDP is <strong>connectionless</strong>. It sends data without first establishing
a TCP-style connection.
</p>

<p>UDP does not guarantee:</p>

<ul>
  <li>Delivery</li>
  <li>Ordering</li>
  <li>Retransmission</li>
</ul>

<p>
However, UDP is lightweight and fast.
</p>

<p>Common examples:</p>

<ul>
  <li>DNS</li>
  <li>DHCP</li>
  <li>VoIP</li>
  <li>Streaming</li>
  <li>Online Gaming</li>
</ul>

<p>
<strong>TCP → Reliability</strong><br>
<strong>UDP → Speed / Low Overhead</strong>
</p>

<hr>

<h2>4. TCP 3-Way Handshake</h2>

<p>
Before TCP data communication begins, TCP establishes a connection using a
<strong>3-way handshake</strong>.
</p>

<pre>
Client                         Server

   SYN  --------------------&gt;

        &lt;--------------------  SYN-ACK

   ACK  --------------------&gt;
</pre>

<h3>Step 1 — SYN</h3>

<p>
The client requests to establish a TCP connection.
</p>

<h3>Step 2 — SYN-ACK</h3>

<p>
The server acknowledges the request and indicates that it is ready.
</p>

<h3>Step 3 — ACK</h3>

<p>
The client acknowledges the server's response.
</p>

<p>
The TCP connection is now ready for data transfer.
</p>

<p>
<strong>Remember: SYN → SYN-ACK → ACK</strong>
</p>

<hr>

<h2>5. TCP Connection Termination</h2>

<p>
TCP also has a controlled process for closing a connection.
A common graceful termination looks like:
</p>

<pre>
Client                         Server

   FIN  --------------------&gt;

        &lt;--------------------  ACK

        &lt;--------------------  FIN

   ACK  --------------------&gt;
</pre>

<p>
This allows the connection to close in an orderly way.
</p>

<p>
<strong>Remember: FIN → ACK → FIN → ACK</strong>
</p>

<hr>

<h2>6. TCP Flags</h2>

<p>
TCP uses <strong>flags</strong> to indicate what is happening with a TCP connection.
</p>

<table>
  <thead>
    <tr>
      <th>Flag</th>
      <th>Meaning</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><strong>SYN</strong></td>
      <td>Start or establish a connection</td>
    </tr>
    <tr>
      <td><strong>ACK</strong></td>
      <td>Acknowledge received data</td>
    </tr>
    <tr>
      <td><strong>FIN</strong></td>
      <td>Gracefully close a connection</td>
    </tr>
    <tr>
      <td><strong>RST</strong></td>
      <td>Immediately reset or terminate a connection</td>
    </tr>
    <tr>
      <td><strong>PSH</strong></td>
      <td>Push data to the application</td>
    </tr>
    <tr>
      <td><strong>URG</strong></td>
      <td>Indicate urgent data</td>
    </tr>
  </tbody>
</table>

<p>
For SOC L1, focus especially on:
<strong>SYN, ACK, FIN, and RST</strong>.
</p>

<p>
A large number of SYN packets without responses can be useful during
investigation because they may indicate scanning or a connection problem.
</p>

<hr>

<h2>7. Ports</h2>

<p>
A <strong>port number</strong> identifies a specific application or service
on a device.
</p>

<p>
<strong>IP address</strong> identifies the device, while the
<strong>port</strong> identifies the service or application.
</p>

<p><strong>Example:</strong></p>

<pre>
192.168.1.10:443
</pre>

<p>
Here:
</p>

<pre>
192.168.1.10 → Device
443           → HTTPS service
</pre>

<p>
Port numbers range from:
</p>

<pre>
0 – 65535
</pre>

<hr>

<h2>8. Sockets</h2>

<p>
A <strong>socket</strong> is commonly represented by:
</p>

<pre>
IP Address + Port
</pre>

<p><strong>Example:</strong></p>

<pre>
192.168.1.10:443
</pre>

<p>
For a complete TCP communication, we can identify both endpoints.
</p>

<pre>
Client: 192.168.1.20:51524
Server: 192.168.1.10:443
</pre>

<p>
Together, these endpoints identify the communication session.
</p>

<hr>

<h2>9. Source &amp; Destination Ports</h2>

<p>
Network communication contains information such as:
</p>

<ul>
  <li>Source IP</li>
  <li>Source Port</li>
  <li>Destination IP</li>
  <li>Destination Port</li>
</ul>

<p><strong>Example:</strong></p>

<pre>
Source:
192.168.1.20:51524

Destination:
192.168.1.10:443
</pre>

<p>
Here:
</p>

<ul>
  <li><strong>Source Port</strong> = 51524</li>
  <li><strong>Destination Port</strong> = 443</li>
</ul>

<p>
The server is listening on port <strong>443</strong>, while the client normally
uses a temporary <strong>ephemeral port</strong>.
</p>

<h2>11. Ephemeral Ports</h2>

<p>
An <strong>ephemeral port</strong> is a temporary port usually selected by
the client for an outgoing connection.
</p>

<p><strong>Example:</strong></p>

<pre>
Client:
192.168.1.20:51524

Server:
192.168.1.10:443
</pre>

<p>
Here:
</p>

<pre>
51524 → Ephemeral / Client Port
443   → Server / Service Port
</pre>

<p>
The client can use a different temporary port for another connection.
</p>

<h2>12. TCP vs UDP</h2>

<table>
  <thead>
    <tr>
      <th>TCP</th>
      <th>UDP</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Connection-oriented</td>
      <td>Connectionless</td>
    </tr>
    <tr>
      <td>Reliable</td>
      <td>No delivery guarantee</td>
    </tr>
    <tr>
      <td>Ordered data</td>
      <td>No ordering guarantee</td>
    </tr>
    <tr>
      <td>Retransmission</td>
      <td>No retransmission</td>
    </tr>
    <tr>
      <td>More overhead</td>
      <td>Low overhead</td>
    </tr>
    <tr>
      <td>Usually slower</td>
      <td>Usually faster</td>
    </tr>
    <tr>
      <td>Uses TCP handshake</td>
      <td>No TCP-style handshake</td>
    </tr>
  </tbody>
</table>

<p>
<strong>TCP:</strong> "Did you receive that? If not, I'll send it again."
</p>

<p>
<strong>UDP:</strong> "Here is the data." → Continues without TCP-style delivery confirmation.
</p>

<h2>13. Connection States</h2>

<p>
TCP connections move through different states during their lifecycle.
</p>

<table>
  <thead>
    <tr>
      <th>State</th>
      <th>Meaning</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><strong>LISTEN</strong></td>
      <td>Server is waiting for incoming connections</td>
    </tr>
    <tr>
      <td><strong>SYN-SENT</strong></td>
      <td>Client sent SYN and is waiting for a response</td>
    </tr>
    <tr>
      <td><strong>SYN-RECEIVED</strong></td>
      <td>Server received SYN and responded with SYN-ACK</td>
    </tr>
    <tr>
      <td><strong>ESTABLISHED</strong></td>
      <td>Connection is established and data can be exchanged</td>
    </tr>
    <tr>
      <td><strong>FIN-WAIT</strong></td>
      <td>Device is in the process of closing the connection</td>
    </tr>
    <tr>
      <td><strong>TIME-WAIT</strong></td>
      <td>Connection has closed but state is temporarily retained</td>
    </tr>
    <tr>
      <td><strong>CLOSED</strong></td>
      <td>Connection is completely closed</td>
    </tr>
  </tbody>
</table>

<h2>TCP Connection Flows</h2>

<h3>TCP 3-Way Handshake</h3>

<pre>
Client                  Server

  SYN  ────────────────&gt;

       &lt;───────────────  SYN-ACK

  ACK  ────────────────&gt;

       Connection Established
</pre>

<h3>Data Communication</h3>

<pre>
Client                  Server

  Data ────────────────&gt;

       &lt;─────────────── ACK

  Data ────────────────&gt;

       &lt;─────────────── ACK
</pre>

<p>
TCP can retransmit data if it detects that something was lost.
</p>

<h3>TCP Connection Closing</h3>

<pre>
Client                  Server

  FIN  ────────────────&gt;

       &lt;─────────────── ACK

       &lt;─────────────── FIN

  ACK  ────────────────&gt;

       Connection Closed
</pre>

<h2>SOC L1 Connection</h2>

<p>
When you see network traffic in a SIEM, firewall, IDS, or packet capture,
you should be able to understand the
<strong>source IP, source port, destination IP, destination port, protocol,
TCP flags, and connection state</strong>.
</p>

<p>
<strong>Example:</strong>
</p>

<pre>
192.168.1.20:51524 → 192.168.1.10:443

TCP
Source Port: 51524
Destination Port: 443
Service: HTTPS
</pre>
